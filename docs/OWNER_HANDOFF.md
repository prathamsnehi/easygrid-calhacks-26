# Owner data for voice and simulated settlement — CAL-27

The existing map already bundled owners, parcels, contact references and proposed compensation. CAL-27 adds the missing owner-linked mock banking profiles and one executable shared validation contract, rather than creating another set of unrelated owners.

Every one of the map's 24 fictional owners now has a distinct mock recipient. `createHandoff(...).ownerHandoff` joins the original owner, affected parcel geometry/impact, contact reference, current terms and banking profile. The user role only changes the contact overlay: it never changes the fictional owner's payment identity.

## Start here

From the repository root, using Node 24:

```sh
npm ci --ignore-scripts --prefix packages/contracts
npm run generate --prefix packages/contracts
npm run check --prefix packages/contracts
npm run demo:handoff --prefix packages/contracts
npm test --prefix apps/map-preview
```

These commands use local synthetic inputs. They do not dial a phone, sign an agreement, transfer money or write backend state.

| File | Use |
| --- | --- |
| `packages/contracts/src/owner-handoff.ts` | Strict shared packet, voice projection and guarded settlement-plan helpers |
| `packages/contracts/src/owner-handoff-fixtures.ts` | Fresh sample factories and executable rejection cases |
| `packages/contracts/examples/owner-handoff.json` | Generated sample pack for all three workstreams |

| `apps/map-preview/dist/demo-handoff-example.json` | Actual baseline map route, its affected owners and `ownerHandoff`; generated by the map build |

The two-owner shared-package scenario is deliberately small and independent of the 24-owner map. Its Morgan Reed / Dana Brooks aliases and L001 / L002 geometry are examples in a different session/project, not replacements for the map's fixture records. Do not join data across these two datasets by parcel ID alone.

## One packet, two consumers

`OwnerHandoff` contains:

- Session/project/route IDs, route version and revision, plus `referenceBinding` indicating local fixture IDs or canonical host references.
- Original fictional owners, opaque contact references, registration status and call consent.
- Owner-linked `banking` records: mock recipient reference, simulated mode, holder alias, bank display and masked account display. There are no real bank account or routing numbers.
- Every affected parcel's geometry, owner ID, tower touches, wire length, offer cap and terms/version. Current map packets also include `offerPolicy` with the fixed recommendation and 120% limit rule.
- Explicit proposed/pending/counteroffer/refused/accepted outcomes, confirmation reference and separate land-access consent.
- Construction cost, budget and common rent-comparison horizon; the original user role can remain historical after a reroute.

The map preserves its exact allocated `comparisonRentTotalCents`. Its rounded `monthlyRentCents` may be marked `monthlyRentIsApproximate`; that estimate cannot become accepted terms. Pratham must record an exact agreed monthly amount and recalculate the comparison cost before the agreement-ready check succeeds.

The [offer policy](OFFER_POLICY.md) fixes the recommendation separately from negotiated compensation. For policy-bearing packets, `assertAgreementReady` requires matching authoritative `currentState.offerPolicies`; missing, stripped or changed policies block readiness. `createVoiceHandoff` copies each policy and includes `simulationChecksPassed`, without banking data. The standalone scenario pack below retains legacy policy-free packets for compatibility; the generated map example exercises the current policy.

### Theo → Pratham

Use the existing Agent call callback to privately register the consenting participant with the host. Public `ownerHandoff` contains no entered participant name or phone. Local fixture references remain unregistered even when local startup consent is valid; only the host can establish canonical registration.

```ts
import { OwnerHandoff, createVoiceHandoff } from '@easygrid/contracts';

const packet = OwnerHandoff.parse(mapHandoff.ownerHandoff);
const voiceContext = createVoiceHandoff(packet);
// Pass voiceContext to the adapter; it excludes all banking information.
// The private participant goes through the existing explicit callback separately.
```

This projection never dials. The calling adapter must check current server state, the original role, refusal lockout, consent and registered contact before any live call. `roleOnRoute: false` means the original user is no longer on the current route; it does not authorize reassignment or another call. See [the host binding guide](PRATHAM_HANDOFF.md).

### Pratham → Seohyun

Record structured negotiation outcomes against current IDs/versions. Only explicit accepted terms for every final-route parcel can pass `assertAgreementReady(packet, currentState)`. A completed call or counteroffer is not acceptance. Missing confirmation, refused access, approximate accepted rent, caps, budget and simulation-check failures block readiness.

For standalone development:

```ts
import {
  createOwnerHandoffExamples, OwnerHandoff,
  assertAgreementReady, createSettlementPlan,
} from '@easygrid/contracts';

const examples = createOwnerHandoffExamples();
const packet = OwnerHandoff.parse(examples.packets.accepted);
const context = examples.settlement.contexts.contract;
assertAgreementReady(packet, context.current);
const plan = createSettlementPlan(packet, context);
// plan.status === 'planned'; plan.totalCents === 400000.
// Nothing has been paid. Seohyun's adapter owns execution and ledger persistence.
```

Fixture context factories manufacture trusted-looking state only for tests. A real host must load authoritative current state, signed contracts, approval bindings and settled obligations from its service, not derive them from a submitted packet or accept client booleans as approval. Recheck and persist each state transition atomically. Pure helpers do not supply authentication, durable duplicate protection or provider behavior.

## Worked settlement amounts

The accepted compensation is $12,000 for O001 and $8,000 for O002. Monthly fees are $300 and $200. The fixture additionally sets an invented $100,000 construction cost and $150,000 comparison budget; neither is a real project estimate.

| Stage | O001 | O002 | Total |
| --- | ---: | ---: | ---: |
| Contract compensation, 20% | $2,400 | $1,600 | $4,000 |
| Completion balance | $9,600 | $6,400 | $16,000 |
| First monthly fee | $300 | $200 | $500 |
| Second monthly fee | $300 | $200 | $500 |
| Landowner settlement total | $12,600 | $8,400 | $21,000 |

All machine values are USD integer cents. The contract tranche is `floor(compensationCents / 5)`; the completion balance is the exact remainder. No separate deposit is added. Monthly fees remain separate from compensation.

The illustrative clock records completion on November 1, 2026. The first monthly fee is due December 1, then January 1, 2027. Calendar anniversaries clamp to month end without drifting: January 31 completion gives February 28 and then March 31. There is no pre-completion rent or proration in this demo convention.

Obligation IDs use a JSON tuple of session, parcel, stage and optional rental period. They remain stable if a contract is regenerated or a request key changes. The host must preserve and uniquely enforce these business obligations; regenerating the identifier from a new contract ID would permit duplicate payments.

Prior settlement is represented by `settledObligations` records bound to amounts, terms, owner, recipient, session, route and rent horizon. Balance and monthly records also bind the completion event and date, so moving completion cannot create additional rental periods. A list of paid IDs is insufficient: the helper rejects changed settlement terms after the initial tranche instead of calculating a balance from a different total. Partial retries retain the full-route agreement check but plan only unpaid rows; a fully paid stage is rejected as a duplicate. The sample pack includes 29 executable rejection cases.

## Compatibility and remaining integration

The map envelope remains `easygrid-map-handoff` version 2. Its additive `ownerHandoff` has an independent `easygrid-owner-handoff` version 1. The nested legacy `Snapshot`, old API v1 routes and old deposit/rent fixtures remain unchanged for existing adapters. Do not post the new packet directly to a legacy API v1 endpoint or translate the 20% tranche into an additional deposit.

The new schemas, fixture validations and pure settlement plans are executable. Backend import/registration, persistent user-role binding, authoritative approvals/completion, actual call integration and simulated-payment execution still need their host adapters. Full world/command migration and teammate review remain open in [CAL-27](https://linear.app/easygrid-calhacks-2026/issue/CAL-27); end-to-end connection is [CAL-41](https://linear.app/easygrid-calhacks-2026/issue/CAL-41).
